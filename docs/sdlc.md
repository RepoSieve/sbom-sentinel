# SDLC

This project follows a lightweight SDLC suitable for a capstone team and mentor review.

## Lifecycle

1. **Plan:** choose one issue subtask and confirm the expected output.
2. **Design:** identify the module and data contract affected.
3. **Implement:** make the smallest useful change.
4. **Test:** add or update tests and run them locally.
5. **Document:** update README, docs, or sample output if behavior changes.
6. **Review:** open a focused pull request.
7. **Integrate:** merge after review approval.
8. **Reflect:** update the issue checklist and note the next task.

## Definition Of Done

A task is done when:

- The code or document change is committed in a focused PR.
- The linked issue checklist is updated.
- Tests or sample output show the expected behavior.
- The reviewer can reproduce the result.
- Known limitations are documented.

## Daily Cadence

Each member should aim for one task and one PR per working day. A PR can be small. The purpose is steady progress and reviewable work.
