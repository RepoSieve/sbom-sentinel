# Pull Request Guidelines

## PR Size

Keep PRs small. One PR should solve one reviewable problem.

## Required Sections

Use the repository PR template and fill every section:

- What changed
- Why
- Linked issue
- How to test
- Expected output
- Known limitations
- Review checklist

## Review Focus

The mentor will review:

- Correctness
- Simplicity
- Test evidence
- Documentation clarity
- Whether the work supports the SBOM Sentinel MVP

## Common Reasons For Rework

- Too many unrelated changes in one PR
- Missing run command
- Missing expected output
- No tests or sample evidence
- Missing limitation notes
